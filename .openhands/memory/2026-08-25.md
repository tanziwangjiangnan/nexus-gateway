## 插件系统阶段1+2 — 统一调用端点

### 设计决策
- **端点路径**: `/v1/plugins/{id}/call`（公共 API，免鉴权），不走 `/admin/` 前缀
- **审批缓存键**: `(agent_id, plugin_id, sorted_params)` — 不同于 MCP toggle 的 `(agent_id, provider_name, action)`
- **CLI 超时**: 默认 30s，可在 YAML 按插件覆盖
- **并发**: 默认 false（`concurrent: false`）
- **无 fallback**: 插件不可达时直接返回错误，不触发故障转移
- **Fiber 注册**: 成功调用后注册逆操作到 Fiber 树，`fiber_fail` 自动回滚
- **占位符替换**: `_format_string(template, params)` 支持 `{key}` 占位符，用于 CLI 命令模板

### 测试结果
- `web_search`（http）: Tavily 401（预期，无 API key），链路通
- `send_email`（cli）: capabilities 拒绝 `openhands`（无 `destructive`），正确
- 未知插件 `nonexistent`: 404
- `_format_string`: 正确替换 `{to}` `{subject}` `{body}` 等占位符

## 阶段3 — Agent 插件发现

### 改动
- `GET /admin/agents/declaration` 新增 `?agent_id=xxx` 参数
- 返回该 Agent capabilities 可覆盖的插件列表（capabilities 过滤）
- 未知 Agent 或无 capabilities 时只返回 `read` 插件
- 不传 `agent_id` 时返回所有插件

### 测试结果
- openhands (read/write/execute) → 只看到 web_search（read），看不到 send_email（缺 destructive）
- hermes-checker (read/validate/inspect) → 只看到 web_search（read），看不到 send_email（缺 write+destructive）
- unknown → 只看到 web_search（read 兜底）

- 去重写入 plugins 段（已有插件跳过）

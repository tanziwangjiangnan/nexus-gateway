# 2026-08-13 工作日志

## 修复：组件打包后的接口设计缺陷（v2.10）

### 背景
打包后的 `provider_router/` 和 `fiber_tree/` 组件存在接口设计缺陷：
- FiberTree 用类变量 `_fibers` 和 `__new__` 单例，多实例共享状态
- Storage 抽象缺少 `add_global_call_history` / `get_global_call_history`，`FiberTree._add_global_call` 用 `hasattr` 判断存储类型
- Provider Router 权重/评分公式硬编码，无法扩展

### 改动

**fiber_tree/storage.py**
- `Storage` 抽象新增 `add_global_call_history()` / `get_global_call_history()` 抽象方法
- `MemoryStorage` 和 `SQLiteStorage` 均实现

**fiber_tree/fiber.py**
- `FiberTree._add_global_call()` 改为调用 `self.storage.add_global_call_history()`，移除 `hasattr` hack

**provider_router/router.py**
- `Router.select_provider()` 新增 `weight_fn(provider_cfg, state) → float` 可选参数

**provider_router/monitor.py**
- `CircuitBreakerMonitor` 新增参数：
  - `error_threshold` / `recover_threshold`（默认 0.20 / 0.10）
  - `quality_factor_fn(scores) → float`（默认 0.5 + avg/100*0.5）
  - `user_factor_fn(feedbacks) → float`（默认 1 + total*0.1, 范围 0.5~1.5）

### 验证
- 语法全部通过
- `example_router.py`、`example_fiber.py` 正常运行
- 网关重启后路由正常（`unauthorized` 响应证明路由逻辑正确）
- 缺少 `prometheus_client`，用 `uv install prometheus_client` 补齐

### 注意
- `monitor.py` 重写时出了几次重复行问题，最终用外部 Python 脚本写入才干净。文件有中文注释，`cat >` heredoc 会触发 "Cannot execute multiple commands" 限制，需要通过临时脚本文件写入。

## QQ 机器人链路排查 & 修复

### 背景
用户反馈今早 QQ 机器人报错 "LLM 响应错误"。

### 链路排查结果

**三台服务器分布：**
| 机器 | IP | 角色 |
|------|----|------|
| 老机（阿里云） | `106.14.40.189` | NapCat + AstrBot + kb_knowledge |
| 新机（阿里云） | `106.14.20.149` | kb_agent（Open WebUI 已退出） |
| 当前机（京东云） | `117.72.220.114` | Hermes 网关 + OpenHands |

**完整链路：**
```
QQ ──→ NapCat(老机:3001) ──→ AstrBot(老机:6185)
                                  │
                                  ▼
                            Hermes 网关(京东云:8643)
                                  │
                                  ▼
                            DeepSeek LLM
```

### 根因
**SSL 证书验证失败** — AstrBot 配置中 `hermes` provider 的 `api_base` 写的是 IP `https://117.72.220.114:8643/v1`，但 nginx 的 SSL 证书绑定域名 `hermes.jiangnande.cloud`，IP 直连触发证书验证失败。

日志关键报错：
```
[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: IP address mismatch, certificate is not valid for '117.72.220.114'
```

### 修复
将 `cmd_config.json` 中 `hermes` provider 的 `api_base` 从 `https://117.72.220.114:8643/v1` 改为 `https://hermes.jiangnande.cloud:8643/v1`，然后重启 AstrBot 容器。

### 验证
- Hermes 网关本地测试正常响应（`deepseek-v4-flash` 模型返回正常回复）
- AstrBot 重启后成功启动，日志无报错
- `aiocqhttp(OneBot v11) 适配器已连接` → QQ 适配器连接成功
- 域名 `hermes.jiangnande.cloud` 解析到 `117.72.220.114`，SSL 证书匹配

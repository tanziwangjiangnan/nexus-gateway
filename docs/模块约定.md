## 2. 落位规则（新代码放哪）

| 你要写的东西 | 放哪 | 例子 |
|---|---|---|
| 纯逻辑、可单测（选路、分类、降级决策、能力打分） | `provider_router/` 对应模块 | `fallback.plan_pool_fallback()` |
| 有状态 / 有 IO（DB、外部 HTTP、文件） | 独立模块 + 显式注入，**不在 app.py 里直接写** | `quota.record_error(conn, ...)` |
| HTTP 路由、参数校验、鉴权 | `ops_gateway_core/api/routes_*.py`（拆分后）；app.py 只装配 | 待拆：`routes_admin.py` |
| CLI 子命令 | `gateway.py` + `ops_gateway_core/ops/commands.py` | `gateway.py probe` |
| 一次性脚本 / 实验 | `/root/experiments/`，**不进本仓库** | `bench-light.py` |
| 跨机运维脚本 | `/usr/local/sbin/`（部署时由文档登记） | `model-fingerprint-check.py` |

## 3. 每个模块的最低要求

1. **文件头 docstring**：职责 / 被谁调用 / 关键不变量。
2. **对外函数 docstring**：入参、返回、**副作用**（写 DB、改状态、发网络请求必须写明）。
3. **同名测试**：`tests/test_<模块>.py`；纯逻辑模块要求「每种分支至少一个用例」。
4. **纯逻辑优先**：不读 `os.environ`、不直连 DB、不发网络请求 —— 需要这些东西就由调用方注入。
5. **注释解释「为什么」**，不复述「做什么」；改动用 `# [日期] 原因` 标记（沿用现有风格）。

## 4. 依赖方向（不要反向）

```
gateway.py（入口）
   ↓
ops_gateway_core（装配 / IO）
   ↓
provider_router、fiber_tree（纯逻辑）
```

- `provider_router` **不得** import `ops_gateway_core`、fastapi、httpx。
- `api/app.py` **只做装配与转发**：允许鉴权、读配置、调模块、构造响应；**不再新增业务判断**。
- 新增业务判断如果只有几行、但属于某个关注点，也要放进对应模块（哪怕函数只有 5 行）。

## 5. 改功能的流程（硬性）

1. 先改 / 加模块（带测试）。
2. `python3 -m pytest tests/ -q` 全绿。
3. 再改 `api/app.py` 接线（只加调用，不搬家逻辑）。
4. 重启前自检：`python3 -c "import ops_gateway_core"`（防止语法/导入错误把生产打挂）。
5. `systemctl restart gateway.service`，实测**一个正常路径 + 一个失败路径**。
6. 按《操作手册》留痕（改了什么 / 为什么 / 备份 / 回滚）。

## 6. 不要做（反面清单）

- 往 `api/app.py` 里加新的业务分支（应抽模块）。
- 模块内直接 `os.environ[...]`、`sqlite3.connect(...)`、`httpx.get(...)`（应注入）。
- 把一次性脚本、`.bak.*` 备份提交进仓库（`.gitignore` 已覆盖 `*.bak.*`）。
- 改代码用 SIGHUP 热加载（SIGHUP 只重载 YAML；**改代码必须 restart**）。
- 在没跑测试、没做导入自检的情况下重启生产网关。

> ⚠️ **搬家时的两条硬性检查**（v3.16 踩过两次坑，已固化为自检）：
> 1. **反向引用**：被搬块里**定义**的局部名，若别处仍在用（例：`_APPROVAL_TTL`、`_scoring_state`），
>    必须在块外重建或抽成共享常量，否则原处变成未定义名字（NameError，且往往只在冷路径才炸）。
> 2. **未定义名字自检**：抽完后用 AST 检查「app.py 内所有自由名字是否都能解析」再重启。

## 8. 试点记录

**2026-09-18 第 1 个试点**：把降级链决策从 `app.py` 抽到 `provider_router/fallback.py`。

- 抽出：`pool_model()`（挑模型）、`plan_pool_fallback()`（给下一步计划），都是纯函数。
- 留在 app.py：`_advance_failure()` 只负责把计划应用到 `current_pool / model / model_filter / pool_cfg`。
- 收益：app.py 少 ~28 行、决策逻辑可单测（`tests/test_fallback.py` 8 个用例）、以后改降级规则不用碰 HTTP 层。
